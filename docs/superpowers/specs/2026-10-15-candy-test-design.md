# 糖果测试设计

日期：2026-10-15

状态：设计稿，供用户审阅；尚未开始实现。

## 目标与已确认范围

在左侧导航新增独立的“糖果测试”页面，提供“API 自动测试”和“Codex 自动测试”两个标签页。两种调用方式使用同一道糖果题、同一套判分和统计规则。

用户已确认：

- 使用独立页面。
- 使用 `<final-answer></final-answer>` 标记最终答案，不能依据正文是否出现数字 21 判分。
- 只展示当前批次，不保存历史记录。
- 固定轮数逐轮执行；失败记入该轮，继续下一轮，不自动重试或补测。
- 界面能够查看测试题目。
- API 和 Codex 的请求超时默认均为 600 秒（10 分钟），支持在界面上修改。

第一版不增加五道编程题 TPS 测试、Juice 探测、指纹采集、历史管理、人工改判或多模型对比。每轮糖果测试仍展示耗时和用量，以及数据可用时的端到端 TPS。

## 页面与配置

导航顺序为“模型测试”“糖果测试”“指纹库管理”，原有页面名称保持不变。

糖果测试页面自上而下包含：

1. 页面标题和“查看测试题目”折叠区。
2. API／Codex 标签页及对应配置表单。
3. 测试轮数、超时设置、开始测试及停止后续测试按钮。
4. 执行进度、统计摘要和每轮结果表。

API 配置：Base URL、API Key、模型名、接口格式、可选温度。接口格式显式选择 OpenAI Chat Completions 或 Anthropic Messages，默认 OpenAI Chat Completions。糖果测试不使用自动协议回退：原有 API 函数在自动模式下可能重试并切换协议，与本功能“不自动重试”的规则不一致。

Codex 配置：可执行文件路径与自动检测、路径来源／版本／登录状态、模型列表与刷新按钮、任意模型名输入、推理强度、读取 Codex 用户配置开关。复用现有能力，模型列表不按输入过滤，自动检测出的完整路径必须显示。继续仅支持 Windows；读取用户配置时兼容 Codex++，不推测或管理代理状态。

Codex 路径、模型、推理强度和配置模式复用现有偏好机制。测试结果与 API Key 不写入浏览器持久存储，也不写入本地历史文件。

首版配置与默认值：

- 测试轮数为 5，允许输入 1～50 的整数。
- API 和 Codex 均提供“请求超时（秒）”数字输入框，默认 600 秒（10 分钟），允许输入 30～1800 的整数；该设置作用于每一轮请求，不是整个批次的总时长。
- Codex 推理强度沿用现有选项和已保存偏好；API 温度可留空，使用上游默认值。

开始执行后固定本批次配置，相关输入禁用，防止执行过程中混用模型或参数。结果区显示本批次的调用方式、模型和配置摘要，切换标签页不改变已产生结果的归属。

## 题目可见性与唯一来源

题目在后端定义，拥有稳定标识 `candy-v1`，标准答案为整数 21。API 与 Codex 都从这一定义构造用户提示词。

“查看测试题目”默认折叠，运行前即可展开，展示完整题干、糖果数量表格及最终答案格式要求。内容只读，不提供编辑入口。

题目展示必须来自后端返回的实际用户提示词，不能在前端另维护一份近似文案。以保留换行的纯文本呈现；标签应作为文字可见，不能被浏览器当作 HTML 解释。

开始批次时保存题目标识和提示词的内存快照。运行中以及运行结束后，用户均可从结果区查看“本次测试题目”。该快照与实际发送的用户提示词完全一致，不包含标准答案。这里展示的是应用提交的用户题目，不声称包含 Codex 或上游追加的系统提示词。

题目文字沿用参考项目 `.temp/referrences/codex-candy-eval/codex_candy_eval.py` 中的糖果题，并增加统一格式要求。实现时将题目作为应用自身的定义，运行时不依赖被忽略的 `.temp` 目录，也不启动参考项目脚本。

最终发送的用户提示词：

```text
不使用任何外部工具回答以下问题：

在一个黑色的袋子里放有三种口味的糖果，每种糖果有两种不同的形状（圆形和五角星形，不同的形状靠手感可以分辨）。现已知不同口味的糖和不同形状的数量统计如下表。参赛者需要在活动前决定摸出的糖果数目，那么，最少取出多少个糖果才能保证手中同时拥有不同形状的苹果味和桃子味的糖？（同时手中有圆形苹果味匹配五角星桃子味糖果，或者有圆形桃子味匹配五角星苹果味糖果都满足要求）

        苹果味  桃子味  西瓜味
圆形       7      9      8
五角星形   7      6      4

请给出解题过程，并在回答最后使用 <final-answer>整数</final-answer> 输出最终答案。该标签只能出现一次，标签内不要包含单位、解释或其他内容。
```

标准答案仅用于后端判分，不拼接进模型请求。题干、格式要求或判分规则改变时更新题目版本，避免同一标识代表不同测试。

## 判分规则

判分只处理正常完成的回答文本，不读取模型的推理字段，也不执行模型生成的内容。

- 必须且只能出现一组大小写一致、无属性的 `<final-answer>` 和 `</final-answer>` 标签。
- 结束标签之后只允许空白字符；标签必须位于最终答案位置。
- 标签内容去除首尾空白后必须完全匹配十进制整数，可带正负号，不接受小数、中文数字、单位或说明文字。
- 标签内外可以换行，前面的解题过程不参与数值比较。
- 解析出的整数等于 21 时判“正确”，其他整数判“错误”。

缺失、重复、嵌套、未闭合、带属性、内容非法或结尾格式不符合要求时判“待判定”，返回明确的格式原因，并保留完整回答。不得退回“正文包含 21”规则，也不自动追加追问修复格式。

执行失败、上游结构化拒绝标志、明确报告截断或内容过滤、空回答或无可用回答结构时判“调用失败”，保留实际错误含义；不能把失败当作答案错误。正常完成的非空文本即使写着“无法回答”，也不得靠关键词推测为调用失败；缺少答案标签时按格式规则判“待判定”。失败时有可用的部分回答或用量则保留，但不对部分回答作正确性判定。

## 执行流程与停止

浏览器负责当前批次的顺序编排，每轮调用一个后端单轮接口，不创建后台持久任务或任务队列。

开始前校验所有配置并获取当前题目；Codex 使用现有状态检查。校验或预检查失败时不开始批次、不清空上一批结果。预检查通过后清空上一批结果，冻结配置与题目快照，开始第 1 轮。

每轮使用新的对话输入，不携带前轮答案。API 每轮发起一次选定协议的模型调用；Codex 每轮启动一次独立的临时 `exec`。应用不重发失败请求、不切换协议、不补足成功轮数。CLI 或代理内部可能自行重试，这不等于应用重启该轮，界面不承诺一次 Codex 调用仅包含一次底层 HTTP 请求。

一轮返回后立即记录结果并更新统计，再开始下一轮。HTTP 错误或网络错误也占用该轮；如果无法确认服务端是否完成，显示实际请求错误，不静默重发。

“停止后续测试”设置停止标记，让当前轮完成或超时，然后不再开始后续轮。未执行轮次标记“未执行”，不计入完成数量或正确率，单独展示其数量。按钮文案和状态必须明确是等待当前轮结束，不假装已取消当前模型调用。

切换标签页或左侧工作区不丢弃当前批次，也不触发重复运行。刷新或关闭页面后批次内存状态丢失，前端不会发起下一轮；已到达服务端的单轮请求可能继续完成或超时。第一版不提供恢复功能。

糖果测试与现有指纹自动测试共享当前页面的运行互斥状态，防止同时启动多个批次；切换页面本身仍然允许。

## 统计与结果展示

每轮状态为：等待中、执行中、正确、错误、待判定、调用失败、未执行。

结果表展示轮次、判分状态、提取出的最终答案、输入 tokens、输出 tokens、推理 tokens、耗时、端到端 TPS，以及“查看回答”。完整回答和错误详情均按纯文本呈现，不能渲染执行模型返回的 HTML。

汇总同时显示：

- 计划轮数、已完成轮数、未执行轮数。
- 正确、错误、待判定、调用失败数量。
- 可判定数量与正确率：`正确 / (正确 + 错误)`，显示实际分子和分母。

正确和错误都为零时正确率显示“未提供”，不能显示 0% 或 100%。待判定与失败明确单列，避免只展示百分比掩盖缺失结果。

耗时使用单调时钟，从进入单轮模型调用流程到回答解析结束或失败计算，包含必要的 CLI 启动、模型等待和输出时间，不包含浏览器渲染与批次前置检查。失败轮也记录耗时；浏览器无法取得服务端耗时时显示“未提供”，不混用浏览器计时填充。

端到端 TPS 为 `output_tokens / elapsed_seconds`，仅在正常完成且两项有效、耗时大于零时计算。字段名称或说明明确它不是首 token 延迟或纯解码速度。首版不计算跨调用方式排行榜或额外总分。

用量优先取上游结构化数据，不根据回答长度估算。缺失或无效数据用 `null` 表达并显示“未提供”；实际返回的零应显示为 0。推理 tokens 不重复加到输出 tokens。

用量映射：

- OpenAI Chat Completions：`prompt_tokens` → 输入，`completion_tokens` → 输出，`completion_tokens_details.reasoning_tokens` → 推理。
- Anthropic Messages：输入由 `input_tokens` 加上明确返回的缓存读写输入计数组成；缺失缓存项按未报告处理，不推断额外缓存量。输出取 `output_tokens`；没有独立推理用量时保持缺失。
- Codex：从本次 `turn.completed.usage` 读取输入、输出与可用的独立推理计数。为当前 CLI 实际字段建立脱敏测试样本；没有推理字段时保持缺失，不从模型自述获取。

## 后端边界与复用

新增糖果评测模块，集中管理题目、版本、标准答案和纯函数判分。新增独立路由，复用现有 Flask 应用。

请求层提供结构化完成结果：回答文本、可用 token 用量、完成状态及必要错误信息。API 与 Codex 分别做协议适配，评测层统一计时、判分和组装单轮结果。现有只返回文本的入口保留兼容包装，现有指纹调用的默认重试、协议回退和超时行为保持不变。

API 新入口允许明确选择协议、单次尝试和本次超时。不能直接调用现有带重试和协议回退的 `request_completion(..., api_format="auto")`。不为此复制整套 URL 构造、认证头和响应解析代码；把可共享的底层职责提取为可测试函数。

Codex 复用路径发现、登录、模型目录、用户配置模式、临时会话、只读沙盒及超时进程回收能力，在已有 JSON 事件处理处补充用量解析。糖果测试参数不修改其他测试的运行默认值，也不修改用户 Codex 配置文件。

超时字段应用于 API 的连接／阻塞读取等待和 Codex 执行等待。前后端统一默认值为 600 秒；后端在参数省略时使用该默认值，显式传入时校验其为 30～1800 的整数。界面选择的值必须传递到实际调用层，不能被原有 API 的 240 秒或 Codex 的 120 秒默认等待覆盖，前端也不能使用更短的固定请求超时提前结束等待。API 库的单次阻塞超时不等于严格的整轮总时限；Codex 的路径与登录检查沿用现有短超时。耗时仍记录实际值，页面不展示硬性倒计时或承诺整轮一定在该秒数内结束。

建议接口：

- `GET /api/candy/question`：返回 `question_id`、标题和完整 `prompt`，不返回标准答案。
- `POST /api/candy/api/probe`：接收 `question_id`、Base URL、API Key、模型、显式协议、可选温度及超时。
- `POST /api/candy/codex/probe`：接收 `question_id`、Codex 路径、模型、推理强度、用户配置开关及超时。

单轮接口不接受自定义题目或标准答案。后端验证题目标识，服务版本不匹配时返回 409，不发送模型请求。前端将该轮记为失败并停止后续轮，提示重新获取题目后开始新批次，避免同一批次混用题目版本。

合法请求的评测结果包含 `question_id`、`status`、`answer`、`final_answer`、`grading_reason`、`usage`、`elapsed_seconds`、`tps` 和可空的 `error`。模型调用失败返回结构化的 `status=error`，以便保留本轮耗时和部分输出；请求参数非法返回 400，题目版本不匹配返回 409。两者都不得启动模型请求。

错误展示保持真实含义：可以提取上游结构化错误信息并隐藏凭据，但不根据连接错误改写成“Codex++ 代理未运行”等推断。不记录或返回 API Key、认证头及认证令牌。结果 JSON 中不保存密钥，也不持久化原始请求。

指纹提取、指纹比对、指纹库文件和 `unified_bank.json` 不参与糖果测试。

## 验收标准

1. 左侧有独立入口，API 与 Codex 标签页可用，原有页面仍可正常操作。
2. 运行前能查看完整题目，结果区能查看批次题目快照；页面显示的用户提示词与两种方式实际发送的文本一致，正确答案未拼接进请求。
3. 标签内 21 判正确、其他整数判错误，正文出现 21 不影响判分；缺失、重复、嵌套、未闭合、带单位、小数或末尾多余内容均按格式规则待判定。
4. N 轮严格顺序运行，失败不重试或补测；API 不触发隐式协议回退。停止后不再发送新轮次，已产生结果保留。
5. 用量缺失与零值能区分，结构化错误保留可用耗时；正确率分母排除待判定、失败和未执行，并清楚展示数量。
6. 切换标签页或工作区保留批次和实际配置标识；刷新页面不恢复历史结果，API Key 和答案不被持久化。
7. Codex 路径自动发现、完整路径展示、可输入的完整模型列表、刷新按钮及用户配置模式继续可用。
8. 判分、编排、API 无重试、题目版本、用量解析和旧入口兼容性都有行为测试；UI 验证覆盖题目折叠区、结果明细、停止行为与切换页面。真实模型调用只用于用户授权的联调，不成为自动测试依赖。
9. 两种方式的界面超时默认均为 600 秒且可修改；省略参数时后端同样采用 600 秒，修改值能传递到实际调用，非法值在模型请求前被拒绝；现有指纹测试的默认超时不受影响。
